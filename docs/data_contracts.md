# Source Data Contracts

## Patients Dataset

### Source File

`patients.csv`

### Purpose

Contains demographic, geographic, financial, and lifecycle information for synthetic patients generated by Synthea.

### Expected Grain

One row represents one synthetic patient.

### Candidate Key

`Id`

The `Id` column is the candidate key because:

- Every patient record has an `Id`.
- No duplicated patient IDs were detected.
- In the profiled source file, each distinct Id identifies one patient row.
- The distinct patient ID count equals the dataset row count.

### Required Columns

The following columns must exist in the source schema:

- `Id`
- `BIRTHDATE`
- `DEATHDATE`

### Required and Optional Values

- `Id` is required for every patient record.
- `BIRTHDATE` is required for every patient record.
- `DEATHDATE` may be missing for an individual patient.

### Date Fields and Validation Rules

#### `BIRTHDATE`

- The value is required for every patient record.
- The supplied value must convert to a valid date.
- The converted birthdate must not be later than the pipeline reference date.

#### `DEATHDATE`

- The value may be missing for an individual patient.
- When a value is supplied, it must convert to a valid date.
- The converted death date must not occur before the patient's birthdate.
- The converted death date must not be later than the pipeline reference date.

### Failure Classification

#### Structural Failures

A structural failure means the source file cannot be safely processed as the expected patient dataset.

Examples include:

- `patients.csv` does not exist.
- The file cannot be opened or parsed as CSV.
- The file is empty.
- The header cannot be read.
- One or more required columns are missing:
  - `Id`
  - `BIRTHDATE`
  - `DEATHDATE`

A structural failure stops the patient-file ingestion process.

#### Record-Level Quality Failures

A record-level quality failure means the file is structurally readable, but one or more patient records violate a data-quality rule.

Examples include:

- A patient `Id` is missing.
- A patient `Id` is duplicated.
- A `BIRTHDATE` is missing or cannot be converted.
- A `BIRTHDATE` is later than the pipeline reference date.
- A supplied `DEATHDATE` cannot be converted.
- A `DEATHDATE` occurs before the patient's `BIRTHDATE`.
- A `DEATHDATE` is later than the pipeline reference date.

Record-level quality failures are preserved in the RAW layer and identified during downstream validation. They must not enter trusted analytical models without being detected and handled.
